# Model options: first-hour audit

Audit date: 2026-11-14. This is a source/readiness audit, not a model benchmark. No weights were downloaded and no model or provider inference was run for this audit. Memory figures below are estimates, not measured execution results.

## Recommendation

Prioritize the supplied YOLO11m as an additional, explicitly attributed source of fixture boxes, then give Gemini the shared local evidence, coverage warnings and readable source crops. Preserve disagreements between detectors rather than adding their counts together. Native PDF text and IFC properties should remain authoritative for their directly recorded values; neither a detector score nor agreement between two models proves completeness. Measure this candidate on the same frozen development IDs before promotion. Nothing inspected establishes 90–95% question-answer accuracy.

The supplied detector adds concrete fixture classes missing from the RT-DETR structural head: `electrical_appliance`, `bathtub`, `shower`, `sauna_bench`, `stairs`, `toilet`, and `sink`, alongside `door` and `window`. Its README describes 4,200 CubiCasa training plans and 400 validation plans. It reports epoch-29 detection metrics, but the count table explicitly concerns epoch 26: those scores must not be assigned to the current checkpoint. CubiCasa-derived development drawings may overlap training; provenance/group exclusions are necessary. `sauna_bench` is not synonymous with sauna-room count. Multipane window splitting and excluded common-area doors also require semantic checks. The local checkpoint is 40,569,507 bytes; deployment memory/latency must be measured through the existing worker. See the supplied `../floorplan_detector/README.md`, `infer.py` and `proofplan/v2/registry.json` for the existing contracts. Retain the previous detector and its settings.

## DINOv2-small is not an answer verifier

The official DINOv2 ViT-S/14 backbone has 21M parameters and emits image/patch embeddings (384-dimensional tokens), not text answers, OCR, instance counts or correctness judgments. Standard code/weights use Apache-2.0 and official downloads/Torch Hub are provided. About 84 MB of FP32 parameters is a size calculation, not measured process memory. It is plausible on CPU or GPU, but adding it cannot verify that a room count, printed area or pipe specification is true. [Official implementation and downloads](https://github.com/facebookresearch/dinov2), [output contract](https://github.com/facebookresearch/dinov2/blob/main/MODEL_CARD.md), [license](https://github.com/facebookresearch/dinov2/blob/main/LICENSE).

A future useful role is cached similarity/duplicate detection or an experimentally validated unfamiliar-drawing flag. A similarity score would still not prove answer correctness. For this iteration, cache existing structured detections, text and geometry by source hash plus extraction/model/configuration version; answer reuse additionally needs question and scope. Preserve per-model evidence IDs and source-coordinate boxes. Cached feature retrieval must not be reported as cold inference speed, and embeddings alone do not replace readable spatial evidence.
